Пауза между фрагментами — самый длинный интервал между двумя соседними непустыми SSE-фрагментами одного ответа после начала выдачи. На Max клиент мог получить первый фрагмент и ждать следующего больше минуты, пока движок обрабатывал другой вход.

Время Long охватывает три измеряемых батча после прогрева, по 256 выходных токенов на запрос. Время Max охватывает один батч с теми же сохранёнными входами и лимитом 16384 на ответ. На четырёх клиентах суммарный выход Max изменился с 27172 до 4977 токенов, поэтому разница времени включает и эффект длины ответов. События на node3: /var/tmp/strata-overlap.DEZESK/ (0,5) и /var/tmp/strata-share0.knwRqo/ (0).

Общее окно decode начинается с первого непустого фрагмента последнего вступившего клиента и заканчивается последним фрагментом первого завершившего. При отсутствии пересечения указано 0 с. TTFT включает prefill. Для Max C=1 он измерен движком, для остальных завершённых случаев — клиентом.

Скорость Short и Long при C=1 рассчитана по фактическому выходу минус первый токен и времени от первого токена до конца ответа. Для Short C=2 и Long C=2/4 приведено среднее штатных скоростей decode отдельных запросов, для Max C=2/4 — диапазон. Суммарная скорость в общем окне требует точных счётчиков токенов в потоке; сервер их не вернул.

Минимум MemAvailable в снимках под нагрузкой для Long C=2/4 составил 51,49 / 51,47 GiB, для полного Max C=2/4 — 48,91 / 49,27 GiB. Минимум MemFree среди этих снимков — 41,38 GiB. Во время prefill Max C=1 было доступно 49,7 GiB. Резерв ОС — 10 GiB, swap процесса — 0.

В снимках Long и Max при C=2/4 HTTP-очередь (queued) и ожидание слота (admitting) оставались нулевыми. Во всех трёх сериях Long ответы по 256 токенов выдавались по очереди. В одной серии полного Max при C=4 два потока за 23,786 с передали 2525 и 2100 непустых SSE-фрагментов. Один клиент достиг лимита 16384, остальные завершили ответ раньше.

Отдельная проверка Short на двух клиентах (512 и 514 входных токенов, повторно использовано 0) показала waiting=1 во время prefill.

На Short все клиенты выдавали фрагменты ответа в общем окне каждой из трёх серий. Для двух клиентов окна составили 2,033 / 2,009 / 2,039 с, для четырёх — 3,566 / 3,647 / 3,453 с. В каждой четверти каждого окна от каждого клиента получено минимум 50 фрагментов при C=2 и 54 при C=4. На Long C=2 снимок показывает одновременные prefill и decode разных запросов; перекрытие двух decode не установлено. Счётчик waiting отражает ожидание канала управления движком, admitting — ожидание свободного слота.

Два независимых диалога примерно по 244000 токенов вернули собственные результаты вызова lookup_record и три маркера из начала, середины и конца документа. Модель распознала на изображении красный квадрат, синий круг и код STRATA47, затем воспроизвела код и маркеры по истории. При отмене во время decode сервер зарегистрировал disconnect и освободил слот. Следующий запрос получил правильный ответ 42 на 37 + 5.

Два слота дали наибольшую суммарную скорость. При переходе с четырёх на шесть скорость на клиента снизилась на 40%, а первый токен пришлось ждать около 29,6 минуты вместо 7,1 минуты.

Decode посчитан в интервале от первого токена последнего вступившего клиента до последнего токена первого завершившего. TTFT включает обработку входа. Для 1/2/4 показана измеряемая серия llama-benchy после прогрева; для 6 — одна серия одновременных SSE-запросов из сохранённых Max-входов с холодного старта сервера. Память — минимум MemAvailable ОС и пик занятой VRAM по замерам.

При шести клиентах общее окно decode длилось 472,5 с. Swap процесса — 0, трассировка не зарегистрировала физических чтений файлов весов кроме PLE. В прогонах 2/4 файловой трассировки не было. Семь клиентов остановлены оператором на prefill. Для восьми один запуск прерван для замера одного слота, другой — тайм-аутом клиента на 300 с, ещё один — при показании очереди 1 на этапе допуска. Завершённого замера скорости для 7/8 нет.
